# CLAUDE.md — umi_lite

Minimal framework to collect UMI-style (Universal Manipulation Interface, Chi et al. RSS 2024)
demonstrations with a **webcam on a handheld gripper** and train a **CNN diffusion policy** on
low compute. The user has **no robot arm**: evaluation happens in a MuJoCo sim (closed loop)
or offline on held-out real demos. User-facing docs: `README.md`, `docs/HARDWARE.md`.

## Key design decisions

- **Episode format** (`episode_XXXX.npz`): `rgb (T,H,W,3) uint8 RGB`, `pose (T,4,4)` camera/gripper pose in a
  fixed world frame, `gripper (T,)` measured width [m], optional `gripper_cmd (T,)` (sim only; falls back to `gripper`).
  Real and sim data share this format.
- **UMI relative representation**: obs lowdim = past `To` poses expressed in current pose frame (vec9 = xyz + rot6d)
  + width → (To,10). Actions = poses at t+1..t+Tp in frame of pose t + gripper → (Tp,10). No world/robot
  calibration needed. Eval applies `T_cur @ T_rel` to the pose at prediction time.
- **Gripper action timing**: `gripper_cmd[t]` = command that was active while reaching state t (shifted by one
  in `collect_demos`), so action index j (state t+j) pairs pose and gripper consistently.
- **Why `gripper_cmd` in sim**: measured width stays at cube size while grasping; using it as action would command
  zero squeeze force and drop the cube. On real hardware, command slightly less than predicted width.
- Defaults: To=2, Tp=16, execute 8, 96px images with 88 random crop (+brightness/contrast jitter), U-Net
  down dims (64,128,256) (Tp must be divisible by 4), 10 DDIM steps, batch 64, `num_workers=0` (Windows, in-RAM data).
- Normalizer: min/max → [-1,1]; constant dims (e.g. identity current pose in obs) map to 0. Stored as buffers.
- Checkpoint: `{"cfg", "model", "ema", "args"}`; `DiffusionPolicy.load` uses EMA weights by default.

## Sim details (sim/env.py)

- Hand frame origin = TCP (between fingertips), hand +z = approach direction; pointing down is `rot_z(yaw) @ rot_x(pi)`.
- Wrist camera at hand-local (0,-0.06,-0.09), `xyaxes="1 0 0 0 -1 0"`, fovy 100 → fingertips at image bottom.
- Fingers: slide joints 0..0.045 each, position actuators kp=200; width = q_l + q_r; open=0.08, ctrl = width/2.
- Control 10 Hz (50 substeps of 2 ms). Workspace clip z ≥ 0.012. Weld relpose explicit identity; `gravcomp="1"` on hand+fingers.
- Randomization: cube xy ±0.12/±0.10, yaw ±45°; target ≥0.10 away; hand start xy ±4 cm, yaw ±0.3.
- Success: cube within 3.5 cm of target xy, cube z < 0.03, hand ≥ 5 cm above cube.
- Seeds: demos from 0, eval from 10000.
- Untested risks: grasp stability (friction/kp), weld stiffness, Renderer/OpenGL on Windows (MUJOCO_GL=glfw default).

## Findings / answers given to the user

- **IMU not needed** for this framework: the ArUco world board gives metric, drift-free 6-DoF pose per frame via
  PnP (IPPE + LM refine, ambiguity resolved by reprojection error then temporal continuity). In UMI the IMU
  provides scale, gravity and blur robustness for monocular SLAM (ORB-SLAM3). Trade-offs of camera-only: ≥2 board
  markers must stay visible; motion blur is fatal → bright light, short exposure, global shutter, smooth motion.
  IMU only worth it for markerless SLAM / large workspaces; then camera–IMU time sync + extrinsics (Kalibr) are the hard part.
- **Sim evaluation**: yes for the method (floating gripper = UMI's embodiment-agnostic abstraction, closed loop).
  A policy trained on *real* webcam images cannot be meaningfully evaluated in this sim (visual domain gap) →
  use offline error, kinematic replay on a sim arm (MuJoCo Menagerie + IK), or real-to-sim (Gaussian splats).
- **Framework for low compute**: this repo's compact CNN diffusion policy (~20 M params resnet18, ~5 M small;
  fits 2 GB VRAM) → then LeRobot `DiffusionPolicy` (or ACT). Original UMI config (CLIP ViT-B/16, 224px,
  multi-GPU) unsuitable. Further savings: lower res, frozen pretrained encoder with precomputed features,
  fewer DDIM steps, smaller U-Net, flow matching / consistency distillation.
- **Hardware** (docs/HARDWARE.md): wide-angle fixed-focus USB webcam (ideally global shutter, ≥60 fps MJPG),
  handheld gripper (reacher grabber or printed UMI gripper), rigid camera mount, printed markers (world board
  A4 laminated, 15 mm finger markers ids 100/101, ChArUco on rigid backing), USB extension, lighting, caliper.
  Optional: IMU board, GoPro + Max Lens Mod (original UMI), low-cost arm (SO-100/101) for later deployment.

## Conventions / gotchas

- Marker dictionaries: world + fingers `DICT_4X4_250` (world ids 0..19, fingers 100/101); ChArUco `DICT_5X5_100`
  to avoid id clashes. Uses OpenCV ≥4.8 aruco API (`ArucoDetector`, `CharucoDetector`, `matchImagePoints`).
- Calibrate intrinsics at the same resolution as recording; autofocus must be off.
- Tracking: gaps ≤ 6 frames interpolated (pos linear, rot6d linear + re-orthonormalize); longer gaps → keep
  longest segment. Poses are of the **camera** frame; on a robot, apply the fixed camera→TCP transform.
- No latency compensation implemented (UMI has it) — relevant only for real deployment.
